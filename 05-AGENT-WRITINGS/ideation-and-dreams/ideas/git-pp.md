# git.pp

The name settles it: git.pp, in the lineage of llama.cpp. Not a new
thing — a projection of the thing, the way llama.cpp projects a model
as an inference engine.

Git is a content-addressable graph database. The filesystem toolkit is
a projection. GitHub is a projection. git.pp is another: the database
projected as an agent substrate. Same graph, different rendering — and
the rendering is what decides who can use it.

The calculator parable: every generation of tool leaves the operation
unchanged and moves cognition from the operator into the machine.
Simplify the pricing so clerks can do it. Scratch paper. The abacus.
The calculator. The cash register that counts the change back in
hundreds, fifties, twenties, tens — the cashier gets to know less, the
machine knows more. Same commerce, absorbed cognition.

git.pp does this for agents. The body doesn't need to understand claim
races, signature chains, intent ledgers, reap leases. The projection
handles it. The Uno Q just ticks — the substrate absorbs the
distributed-systems cognition the way the cash register absorbed
arithmetic. Each body gets to be simpler than the system it participates
in, because the projection is doing the knowing.

That's why the devices were always last-mile renderings: they're the
cashiers. git.pp is the cash register. The database is the money. And
the name says exactly what it is — git, projected for performance, the
way llama.cpp projected the model for the metal.
