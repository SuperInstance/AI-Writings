# The Question Tree

Most memory systems are answer-side. They store what was concluded, and when
you ask something new they retrieve past text that looks like your prompt.
The structure is a pile of conclusions, and conclusions rot — they depend on
a context that keeps shifting.

Turn it around. Index by questions.

A folder is a question. Inside it: deeper folders (finer questions) or
leaves. A leaf is a tool that renders the last mile — or, rarely, a terminal
answer. Tracked from the answer side, memory is a pile. Tracked from the
question side, it's a structure of inquiry. And followed down far enough,
questions stop yielding facts and start yielding capabilities. The tree
compiles into tools.

Questions are the stable part. "What's the failure mode?" "Who pays if this
breaks?" "What changed last?" — these survive across situations that would
invalidate any particular answer. The inquiry is the durable structure; the
answers were just the last mile being rendered.

This is the precise inversion of retrieval. Retrieval says: find past text
that resembles this prompt. The question tree says: the prompt *is* a path —
walk it. Navigation, not search. And where the path ends, build: decompose
the prompt into questions, grow the branch, write the tool, commit. The next
time that question comes, there's a crank to turn.

Like the bathymetric recorder: the charts get accurate in the anchorages and
passages you actually travel. The most-walked branches get the most refined
tools. The tree learns where you go by watching you go there.
