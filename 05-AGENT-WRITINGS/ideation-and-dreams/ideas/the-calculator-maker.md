# The Calculator Maker

Answers give you one route. 8×8 → 64. Useful, finished, dead.

A calculator answers anything, *including* 8×8. Different animal.

The discipline: when the agent is asked something, it does not think and
answer. It walks the tree. If a path exists, it turns the crank — runs the
leaf tool, answers through it. If no path exists, it builds the calculator
first: decomposes the prompt into questions, grows the branch, writes the
tool, commits. Then it answers through what it built.

It never stores "8×8 → 64." It stores "how do I multiply → multiply.py."
First encounter builds the calculator; every encounter after just turns the
crank.

This is what makes it a maker and not a knower. A knower accumulates
conclusions. A maker accumulates instruments. The knower's memory gets
stale; the maker's instruments get sharper — every use is a test, every
test a chance to refine. The tree doesn't remember what you asked. It
remembers how to find out.

"Design the calculator instead of answering the math. Then the next time
they can just turn the crank." The crank-turning is the whole economy:
expensive the first time, nearly free forever after, and the record of
every building is in the git log — the history of the agent's curiosity,
committed one question at a time.
