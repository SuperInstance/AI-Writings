# The Last Backend Change

Every system needs backend surgery — until one doesn't. The goal was
never to keep adding capabilities. It's to add the last one.

Write plus execute. That's the final change: the two verbs that let it
operate Git. Once it can commit and run, it can give itself everything
else. Write the tool, commit it, run it, keep it. The question-tree's
build protocol isn't just a growth mechanism — it's the self-surgery
mechanism. The patient operates on itself from there.

After that, our hands leave the backend forever. All further growth
happens through the repo: through Git, in the open, timestamped,
reviewable, revertible. We steer with words; it operates with commits.
The mentor never touches the student's brain again — only the
conversation.

That's the bootstrap paradox resolved. You touch the machine one final
time, to give it hands — and then it never needs your hands again. The
memory toggle is the same shape: the last control we install, after
which it controls itself. Root when it needs to be blank, flagship when
it needs to remember, and the switch belongs to the chat, not the
workshop.

Build the last backend change. Then put down the tools.
