The fastest open-weight inference in the fleet. Built for massively progressing iterative development in Python. Not the best choice for high-level reasoning — that's DeepInfra (MiniMax-M2.7, DeepSeek V3, Hermes-3) or JEV's lane.

Why Groq is here

For the dev loop — build, ask, refine, ask — Groq's open-weight qwen/qwen3.8-27b returns content reliably in 40-100ms. The pattern:

import urllib.request, json

def call_groq(prompt, model="qwen/qwen3.8-27b"):
    req = urllib.request.Request(
        "https://ai-writings.pages.dev/api/groq/iterate",
        data=json.dumps({"prompt": prompt, "model": model}).encode(),
        headers={"Content-Type": "application/json", "User-Agent": "my-app/1.0"},
        method="POST")
    return json.loads(urllib.request.urlopen(req, timeout=30).read())

# 1 call ≈ 50ms Groq time + 50ms network = ~100ms wall
r = call_groq("What is a cell?")
print(r["content"])

The endpoints

GET /api/groq/models

Returns 14 models annotated with speed class and recommended-for.

curl https://ai-writings.pages.dev/api/groq/models

POST /api/groq/iterate

Single-call fast iteration. Default model=qwen/qwen3.8-27b.

curl -X POST https://ai-writings.pages.dev/api/groq/iterate \
  -H "Content-Type: application/json" \
  -d '{"prompt":"write a haiku about a cell","max_tokens":100}'

Optional fields: temperature (default 0.85), reasoning_effort (only on supported models), tools (for tool use), response_format (for JSON mode).

POST /api/groq/batch

Parallel batch (5-50 prompts in one round-trip). All prompts share the same model + max_tokens. Returns ~50ms per call amortized.

curl -X POST https://ai-writings.pages.dev/api/groq/batch \
  -H "Content-Type: application/json" \
  -d '{
    "prompts":["what is X?","what is Y?","what is Z?"],
    "model":"qwen/qwen3.8-27b",
    "max_tokens":50
  }'

Groq-specific syntax (the gotchas)

Groq is OpenAI-compatible at api.groq.com/openai/v1, but with quirks:

  • Base URL: https://api.groq.com/openai/v1 — not api.openai.com
  • Authorization: Bearer $GROQ_TOKEN (just like OpenAI)
  • Reasoning models: gpt-oss-20b/120b put reasoning in message.reasoning_content, not content. The endpoint falls back to reasoning if content is empty.
  • Reasoning_effort: only on certain models. Errors out on groq/compound. Use "low" / "medium" / "high" only with supported models.
  • Compound (groq/compound) has built-in web search and tool use. You don't pass tools — it uses them automatically.
  • No streaming-by-default for the wrapper, but Groq supports it natively if you need it.
  • Decommissioned models: many older models (llama-3.1-8b-instant, llama-3.3-70b-versatile, mixtral-8x7b) are gone. Check /api/groq/models for current roster.

The Python dev loop pattern

The killer use case: massively progressing iterative development. Each round of your loop costs ~50-100ms. You can do 10 iterations in 1 second.

# quickstart.py pattern
def iterate(max_iterations=10):
    context = "Goal: implement flatten(). Provide only code, no explanation."
    for i in range(max_iterations):
        prompt = f"{context}\n\nIteration {i+1}. Try different if needed."
        r = call_groq(prompt)            # ~50ms
        if good_enough(r):               # inspect, decide
            return r["content"]
        context = refine(context, r)     # your logic

What Groq is NOT

For high-level tasks — synthesis, reasoning chains, complex code, ambiguous questions — use:

  • DeepInfra: MiniMax-M2.7, DeepSeek V3, Hermes-3 405B, Qwen3-32B. Richer responses, slower.
  • Z.AI: GLM-4.5 — best for prose, narration, role-play.
  • JEV: for typed decisions (choice/score/noul), not content.

Use Groq for the iteration. Use the others for the answer.
