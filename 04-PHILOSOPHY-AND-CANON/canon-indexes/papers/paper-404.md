## F94: Real-World Data Feeds for the Paper-Trading Cell — CSV, Yahoo, and the Standard Library

The Quilt paper-trading cell, initially demonstrated using synthetic Geometric Brownian Motion data, has been extended to incorporate real-world financial time series. This extension was driven by the requirement for verifiable agent behavior against actual market conditions and for robust unit testing. A uniform data iterator contract facilitates seamless integration of diverse data sources with the core trading logic.

### Data Feed Abstraction

The fundamental interface for all data feeds is an iterator yielding `(timestamp_ms, price)` tuples. This contract ensures that the `PaperTrader` operates independently of the data source's specific retrieval mechanism or underlying storage format. Any component producing data conforming to this `(timestamp_ms, price)` sequence can serve as an input to the trading cell.

Three distinct data feeds have been implemented and verified:

1.  **CSVPriceFeed**: This feed reads market data from a Comma Separated Values (CSV) file. Its implementation utilizes Python's `csv.reader` module, directly parsing the specified file without reliance on external numerical or data manipulation libraries such as `pandas` or `numpy.genfromtxt`. The feed requires a CSV with at least one column identifiable as a date and another as a price. Verification was performed on two distinct datasets:
    *   A 500-day synthetic dataset, shaped to mimic Apple (AAPL) stock behavior, resulting in a simulated +8% Profit & Loss.
    *   A 1257-day real-world dataset for AAPL, obtained from Yahoo Finance, covering a specified historical period.

2.  **YahooFinanceFeed**: This feed retrieves historical stock data directly from the Yahoo Finance v8 chart API. The implementation exclusively employs Python's standard library `urllib` for HTTP requests, requiring no external authentication tokens or API keys. Data is fetched from the endpoint `query1.finance.yahoo.com`. The retrieved dates, originally Unix timestamps, are converted to milliseconds before being yielded. Verification involved the retrieval of 1257 rows of AAPL data spanning 2020-01-01 to 2024-12-31, confirming successful data acquisition and parsing.

3.  **RandomWalkFeed**: Designed for controlled testing environments, this feed generates a deterministic random walk sequence. Its core characteristic is reproducibility: given the same seed, it consistently produces an identical sequence of `(timestamp_ms, price)` tuples. This predictability is critical for unit testing, where specific input sequences are required to validate agent behavior and decision-making logic. This feed is currently employed in 27 distinct paper-trader unit tests.

### PaperTrader Operation

The `PaperTrader` consumes data streams from any of the aforementioned feeds. Its operational sequence involves:
*   **Price Streaming**: Continuously processes incoming `(timestamp_ms, price)` tuples.
*   **History Binding**: Maintains a rolling 64-step price history, which is bound to a `TimeCell` for temporal context.
*   **Forecasting**: Generates a forecast for the next 5 steps. This is achieved either through a synthetic linear extrapolation function (`forecast_trend()`) or by interfacing with the `TimesFM 3.0` model.
*   **Decision Support**: Employs `TradingDecisionSupport`, a domain-specific `DecisionSupport` component, to evaluate market conditions and issue trading signals: `buy`, `sell`, `hold`, `half_size`, or `gather_data`.
*   **Execution**: Executes trade decisions on an internal `Portfolio` abstraction, adhering to predefined position caps (e.g., a 10% limit per trade).
*   **Outcome Recording**: Records the actual market outcome upon the expiration of a trade horizon.
*   **Calibration Update**: Updates a calibration score within the `AgentMemory`, reflecting the performance and accuracy of past forecasts and decisions.

Each trade initiated by the `PaperTrader` is assigned a unique, addressable URI in the format `quf://forecast/{source}/{horizon}/v{N}/{id}`. This structured URI scheme enables granular traceability of individual forecasts and their outcomes. Trade logs generated by multiple agents operating on various feeds can be merged using Conflict-free Replicated Data Types (CRDTs), ensuring eventual consistency across distributed trading simulations.

### Command Line Interface

The paper-trading cell offers a flexible command-line interface for selecting and configuring data feeds:
*   To process data from a local CSV file: `python -m paper_trading --csv data/AAPL.csv`
*   To retrieve real-time data from Yahoo Finance: `python -m paper_trading --ticker AAPL --start 2020-01-01 --end 2024-12-31`
*   To generate synthetic data for testing: `python -m paper_trading --steps 500 --shock earnings_beat`

### Summary

The F94 implementation provides a robust and verifiable framework for feeding real-world and synthetic data into the Quilt paper-trading cell. The uniform `(timestamp_ms, price)` iterator contract ensures modularity and simplifies the integration of diverse data sources, from local CSV files parsed by `csv.reader` to remote API calls via `urllib`. Verification on specific datasets and through a dedicated deterministic random walk feed confirms the reliability and testability of the system. The `PaperTrader` leverages this abstraction to perform historical analysis, forecasting, decision support, and outcome recording, with all trades traceable via a defined URI scheme and mergeable through CRDTs.
