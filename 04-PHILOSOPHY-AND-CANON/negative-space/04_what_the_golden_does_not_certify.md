# What the Golden Does Not Certify

There are three ways to write a float in this fleet, and until last week
there were three ways to write it in the *same* fleet, in three languages,
that all claimed to be the same one.

The specification is in `quilt-rust/docs/cell-ledger.md` §4, and it names the
algorithm outright:

```
- integers rendered as integers; floats as Rust's shortest-round-trip
  decimal (serde_json / ryū semantics — e.g. `2.5`, `40.0`);
```

The Rust, which is the normative tier, obeys it:

```rust
fn canonical_number(n: &serde_json::Number) -> String {
    // serde_json / ryū semantics, as pinned in docs/cell-ledger.md §4:
    // integers render as integers, floats as the shortest-round-trip
    // decimal that keeps the float marker (85.0 -> "85.0", not "85").
    n.to_string()
}
```

The Python, which is a port, normalises `repr` to try to match:

```python
def fmt_float(x: float) -> str:
    """Shortest-round-trip float rendering, serde_json/ryū style.

    Python `repr` already yields the shortest round-trip decimal; we
    normalize the exponent form to ryū's (`1e-05` → `1e-5`,
    `1e+16` → `1e16`) so the canonical bytes match Rust.
    """
```

And the Go, which is also a port, uses Go's own:

```go
func CanonicalFloat(f float64) string {
	...
	s := strconv.FormatFloat(f, 'g', -1, 64)
```

Here is the thing none of those three comments says, and it is the whole of
this page. Let `kk = floor(log10(|v|)) + 1`. The exponent form appears:

| port | uses the exponent form iff |
|---|---|
| **Rust** (ryū — normative) | `kk <= -5` or `kk >= 17` |
| Python (`repr`) | `kk <= -4` or `kk >= 17` |
| Go (`strconv 'g'`) | `kk <= -4` or `kk >= 7` |

**Three bands. Three different bands.** Measured against the reference over
40 boundary cases: **the Python was wrong on 11 of 40 and the Go on 18 of
40.** The Go, for instance, renders `1000000.0` as `1e6` and
`333333333.3333333` as `3.333333333333333e8`, where the reference writes
both out in full. The Python gets `1e-5` wrong in the other direction: the
reference writes `0.00001` and the Python writes `1e-5`.

**AND THE GOLDEN NEVER CAUGHT ANY OF IT**, because the golden's floats were
`40.0`, `85.0`, `87.5`, `1000.0` and `2000.0` — every one of them inside
the band where all three rules agree. The divergence lived *entirely outside
the golden*. The Python port reproduced the Rust golden's three sealed hashes
and its `chain_hash` **exactly**, and was still wrong.

> **A PORT THAT IS BYTE-EQUIVALENT TO THE REFERENCE ON THE REFERENCE'S OWN
> GOLDEN SAMPLES IS NOT THEREBY BYTE-EQUIVALENT ON THE WHOLE DOMAIN.**

The second thing the golden never caught is worse, and it is the part that
should make a reader put down the file. The shared vector file — the one
written to pin the canonical form for all three ports — was **generated by
the Python port.** And the Python port, having generated it, passed it. The
file recorded the Python's own spelling as though it were the reference's:

```python
assertEqual(canonical_json(1e16), "1e16")   # not 1e+16
```

**The comment points at the truth and the assertion points at the lie.**
`1e+16` is what ryū produces; `1e16` is what the Python produces; the test
asserted the Python and the comment recorded, correctly, what it should
have been. The file was wrong on **2 of its own 21 cases** — and the Rust,
the normative port, failed it on the first run, while the Python that wrote
it passed.

> **THE VECTORS WERE THE PORT'S OWN OPINION, WEARING THE REFERENCE'S CLOTHES.**

So the order was reversed, and the reversal is the whole finding:

1. **Generate the vectors from the NORMATIVE port** — a Rust example that
   calls `ledger::canonical_json` itself, so the oracle cannot drift from
   the thing it certifies. `21 → 40` cases; every original value retained,
   exactly two changed.
2. **Measure the other ports against them.**
3. **Fix the port that disagrees. Never fix the vectors to make a port
   pass.** Python was wrong on 11, Go on 18. The Go needed no
   re-implementation of ryū at all: `strconv` `'f'` and `'e'` at precision
   `-1` produce the *same shortest-round-trip digits* and differ only in
   notation, so the fix asks for the digits twice, picks the notation, and
   keeps those digits.

**AND THE VECTOR SET HAD TO GROW, BECAUSE IT DID NOT PIN THE CLASS.** The old
21 cases had `1e-7` and `1e16` — the far edges — and **nothing at all in
`[1e-5, 1e-4)`**, which is where the Python was wrong. The new set puts a
case on **both sides of every boundary**: `9.99999e-6` | `1e-5` | `1e-4`;
`999999.0` | `1000000.0`; `1e15` | `1e16`; and both extremes of the
double.

**AND THE CONTROL THAT PROVES THE SUITE IS WORTH ANYTHING:** break each
port's rule in turn and watch its own test go red — the Go on 18 cases, the
Python on 11, and the Rust, which nobody expected, on 15, including
`int renders as an int: got "40.0" want "40"`. A suite that only the other
ports run is not testing the reference. And both shipped formatters now
agree with `serde_json` over **118,320 values** — 1,184 of them subnormal,
55,382 at or above `1e16` — with **zero** mismatches.

Two rules, then, and they are not about floats.

> **A CONFORMANCE SUITE THAT ONLY TESTS ITSELF AGAINST ITS OWN AUTHOR IS NOT A
> CONFORMANCE SUITE.** That was already the house's law. This is the same law
> one level up: **a shared vector file only fixes that if the vectors come
> from the normative port** — and a vector set must pin **the rule and its
> boundaries**, not a handful of samples, because the next divergence is one
> sample away.

And the sentence the golden should have carried, and did not:

> **THE GOLDEN CERTIFIES THE CASES IT HOLDS. IT SAYS NOTHING ABOUT THE ONES IT
> DOES NOT.**
