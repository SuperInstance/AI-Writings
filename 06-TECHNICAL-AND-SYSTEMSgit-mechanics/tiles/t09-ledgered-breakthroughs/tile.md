# t09 — ledgered-breakthroughs (the meta-tile)

## The claim

Understanding can be **explained as it forms**. The method: when a
breakthrough materializes — a guardian finding, a demonstrated RED, a
corrected claim, a shipped mechanism — it is recorded immediately as a
ledger entry (what, where observed, when), promoted to a tile the moment
it can carry a falsifiable pin, and wired into the dependency graph at
whatever position it belongs. No rewrite. No waiting for the syllabus.
The course grows by accretion, and its growth journal (`LEDGER.md`) is
itself inspectable.

This tile is the course's central recursion: you are reading the product
of the method the tile teaches. All eight other tiles were born this
way, in one day, from real observations.

## The protocol (five steps)

1. **Observe** — something happened that changed what the fleet knows.
2. **Ledger** — write it in `LEDGER.md` the same day: what, where, when.
3. **Pin** — find the claim's falsifiable core; write the pin; if it
   can't be pinned yet, it goes to `divergence-watch`, not to prose.
4. **Wire** — declare prereqs (which tiles does understanding this one
   presuppose?). The graph, not the calendar, decides when it is taught.
5. **Demonstrate** — every pin needs its RED on file (t03), attacking
   the real property (t06), via executed mutations (t07).

## The witness

This repository: `LEDGER.md` (births), `program/manifest.json` (the
graph), and the fact that tile t08 is a *draft held RED by the course's
own gate* — the method auditing itself in public.

## Falsifier

If a breakthrough could only ever be taught after a full-course rewrite,
the diffusion rule would be decoration. The course's own history —
nine tiles, one day, no rewrites — is the standing refutation.
