TypeSafe Edge

Types in. Types out. The boundary is the validator. Cloudflare Workers run Zod schemas at the edge — every byte checked, every error caught.

What is TypeSafe Edge?

A pattern where every Cloudflare Worker / Pages Function has a runtime validator at its boundary. The validator is defined in TypeScript types, but checked at runtime with Zod (or Valibot, ArkType, etc.).

typesafe = (typescript types) × (runtime validation) × (at the edge)

Why this matters: the edge is where untrusted data enters the system. A typesafe boundary means every input is shape-checked, every output is shape-validated, and TypeScript catches every shape mismatch at compile time. The same schema serves as documentation, test, runtime check, and inferred type.

📐 The Pattern

1. Define a schema (the source of truth)

// cell.ts — single source of truth for a cell
import { z } from 'zod';

export const CellSchema = z.object({
  id: z.string().regex(/^[a-z]+:\d+$/),
  kind: z.enum(['ack', 'music', 'voice', 'swarm', 'world', 'crypt', 'pathos', 'ranking', 'partition', 'neighbor', 'audit', 'twist', 'death', 'broadcast', 'chirp', 'chaos', 'thermal', 'feedback', 'lore', 'perception', 'hex', 'flock', 'triage', 'breeder']),
  payload: z.record(z.unknown()),
  ticker: z.number().int().nonnegative(),
  hex: z.string().regex(/^0x[0-9a-f]+$/),
  tag: z.string(),
  meta: z.record(z.unknown()).default({}),
  created_at: z.number().int().positive(),
  updated_at: z.number().int().positive(),
  author: z.string(),
  sig: z.string().nullable(),
  parents: z.array(z.string()).default([]),
  links: z.array(z.string()).default([]),
  witnesses: z.array(z.WitnessSchema).default([])
});

// Type is inferred FROM the schema
export type Cell = z.infer<typeof CellSchema>;

2. Validate at the edge boundary

// worker.ts — every input validated before reaching handler
import { CellSchema } from './cell';

export default {
  async fetch(req: Request, env: Env): Promise<Response> {
    // 1. Parse body
    const body = await req.json().catch(() => null);
    if (!body) return errorResponse(400, 'invalid_json');
    
    // 2. Validate shape (TS sees the return type as Cell)
    const result = CellSchema.safeParse(body);
    if (!result.success) {
      return errorResponse(422, 'validation_failed', result.error.format());
    }
    
    // 3. Now TS knows result.data is Cell — safe to use
    const cell: Cell = result.data;
    
    // 4. Run handler with validated input
    const updated = await handleCell(cell);
    
    // 5. Validate output shape too (defense in depth)
    const outCheck = CellSchema.safeParse(updated);
    if (!outCheck.success) return errorResponse(500, 'handler_corruption');
    
    return Response.json(outCheck.data);
  }
};

3. The same schema is documentation + test + type

// In a unit test: the schema IS the test
test('every cell in corpus validates', () => {
  for (const cell of corpus) {
    expect(() => CellSchema.parse(cell)).not.toThrow();
  }
});

// In OpenAPI docs: the schema generates the spec
const openapi = zodToOpenAPI(CellSchema);

// In TypeScript code: the type is inferred from the schema
function bind(c: Cell, p: Payload): Cell { /* ... */ }

🛠 The Implementation in Cloudflare Workers

Schema (TypeScript + Zod)

import { z } from 'zod';

// Strict schema — every field required
export const TickRequestSchema = z.object({
  prompt: z.string().min(1).max(1000),
  dials: z.object({
    compass: z.number().min(-1).max(1).default(0),
    depth: z.number().min(0).max(100).default(0),
    clarity: z.number().min(0).max(1).default(0.5),
    drift: z.number().min(0).max(1).default(0.5),
    weight: z.number().min(0).max(1).default(0.5)
  }).default({}),
  image_prompt: z.string().max(500).optional()
}).strict();  // reject unknown keys

export type TickRequest = z.infer<typeof TickRequestSchema>;

// Response schema
export const TickResponseSchema = z.object({
  tick: z.number().int().positive(),
  sailor: z.string(),
  dials: z.string(),
  cell: z.string(),
  image: z.string().nullable()
});
export type TickResponse = z.infer<typeof TickResponseSchema>;

Worker entry with typesafe boundary

import { TickRequestSchema, TickResponseSchema, TickRequest, TickResponse } from './types';

export interface Env {
  DEEPINFRA_TOKEN: string;
  CF_TOKEN: string;
}

// Helper for consistent error response shape
function errorResponse(status: number, code: string, details?: unknown): Response {
  return Response.json({ error: code, details }, { status });
}

async function handleTick(req: TickRequest, env: Env): Promise<TickResponse> {
  // ... run 4 parallel API calls ...
  return { tick: Date.now(), sailor, dials, cell, image };
}

export default {
  async fetch(req: Request, env: Env): Promise<Response> {
    if (req.method !== 'POST') return errorResponse(405, 'method_not_allowed');
    
    // 1. Parse
    const raw = await req.json().catch(() => null);
    if (!raw) return errorResponse(400, 'invalid_json');
    
    // 2. Validate input (Zod safeParse)
    const parsed = TickRequestSchema.safeParse(raw);
    if (!parsed.success) {
      return errorResponse(422, 'validation_failed', parsed.error.format());
    }
    
    // 3. Handler (TS knows parsed.data is TickRequest)
    const result = await handleTick(parsed.data, env);
    
    // 4. Validate output (defense in depth)
    const outCheck = TickResponseSchema.safeParse(result);
    if (!outCheck.success) return errorResponse(500, 'handler_corruption');
    
    // 5. Return validated
    return Response.json(outCheck.data, {
      headers: { 'Cache-Control': 'no-store' }
    });
  }
};

Why this works on the edge

  • Zod is small (~12 KB gzipped) — fits in any Worker bundle
  • Validation is fast (sub-millisecond for simple schemas)
  • Same schema = type + validator + doc + test
  • TS catches at compile; Zod catches at runtime; CF edge enforces at network
  • Self-documenting: OpenAPI spec generated from same source

📦 Where TypeSafe Edge applies

  • The Beyond — tick endpoint validates TickRequest, returns TickResponse
  • API Orchestra — each /extensive /massive /ideator route validates its own request/response
  • Quilt Classroom — submission endpoint validates student answers
  • Quilt Cell Zoo — cell parameter changes validated against CellSchema
  • Tensor-MIDI — message schema (speaker, text) validated before processing
  • Polyformalism Explorer — cell builder input validated in real-time
