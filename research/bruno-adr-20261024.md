## 1. The script cannot run in this sandbox at all — three separate reasons, only one of which is the credential

`bruno_adr.py` looks like a one-liner. It is not. Three independent gates, in order:

**a) The paths are hardcoded to the fleet host.** `ADRS_DIR` and `WITNESS_PATH` are
module-level constants pointing at `/workspace/repos/ai-writings/...`. There is no
CLI flag and no env override. On a GitHub runner the checkout is somewhere else
entirely, so both constants have to be reassigned after import
(`ba.ADRS_DIR = BOT / "adrs"`). `snowball-rsi-gan.yml` already does this for
`snowball_writer.py`; the same treatment applies here.

**b) `/workspace` is at 100% NAS quota (600G/600G, 0 avail).** A 5 KB write fails
with `Disk quota exceeded` and leaves a **0-byte file behind** — the file appears in
`ls` with the right name and no content. This is the EDQUOT trap: *a successful
`ls` is not evidence of a successful write.* Always stat the file and check the
size is non-zero before believing it. A `git clone` into `/workspace` dies
mid-clone at `.git/description`. Clone to `/tmp` (overlay, 24 G free) instead.

**c) `ZAI_TOKEN` is absent, and so is every other generative provider key.**
`ZAI_TOKEN`, `GROQ_TOKEN`, `DEEPINFRA_TOKEN`, `DEEPSEEK_TOKEN`, `MINIMAX_KEY` are
all unset. The fleet has hit this for 20+ consecutive sessions — see
`research/snowball-rsi-gan-20261024.md` and the `civilization-orchestrator`
session-73 report on `main`.

## 3. The vault: 403 means "not registered", not "not authenticated"

`POST /proxy` distinguishes the two failures by status code, and the difference
matters:

- **401** `{"error":"OIDC verification failed"}` — the OIDC token is bad. This is
  what you get from the sandbox with any fake token.
- **403** `{"error":"Not authorized","repo":"...","workflow":"...","branch":"..."}`
  — **OIDC verified fine.** The vault parsed the token and echoed the repo,
  workflow and branch back, then refused on its **allowlist**.

`SuperInstance/AI-Writings` is not on that allowlist. The same request from
`SuperInstance/zero-msg-test` returns 200 `{"success":true,"result":{"content":"PROBE-OK",...}}`.
Repo identity is the only variable. `VAULT.md` (in `zero-msg-test`) says a repo
must be registered by opening an issue titled "Register" — that is issue
**#94** in this repo, opened 2026-10-24.

**`&audience=vault` is a no-op.** The request URL already carries `?api-version=2.0`,
so the `&` lands as a second parameter and GitHub honours the default audience
(`aud` = `https://github.com/SuperInstance` either way). The claim that decides
the allowlist is the `sub` claim: `repo:SuperInstance/AI-Writings:ref:refs/heads/main`.
Don't chase the audience when the vault says "Not authorized".

## 4. The route that actually works today: generate in `zero-msg-test`, publish here

`SuperInstance/zero-msg-test` **is** registered and has a generic LLM workflow:

```
POST /repos/SuperInstance/zero-msg-test/actions/workflows/llm-proxy.yml/dispatches
{"ref":"main","inputs":{"prompt":"<full prompt>","out":"<file>","model":"MiniMax-M2.5"}}
```

It writes the completion to `scratch/<out>` in that repo. Read it back with
`GET /repos/SuperInstance/zero-msg-test/contents/scratch/<out>`.

**Do not hand the prompt across as a paraphrase.** Bruno's prompt is built by
`ba.build_adr_prompt(num, title, question)`. Import `bruno_adr` and call it, so
the prompt is byte-identical to what the script would have sent. Same for the
file: call `ba.write_adr(num, title, content)` so the header/footer and the
filename slug match the house style, and `ba.witness("adr_written", payload)` for
the log row. Only the transport changes.

**MiniMax M2.5 emits a `<think>...</think>` block before the answer.** Strip it
with the fleet's own `bots/snowball-scout/vault_provider_shim.py::_strip_think`
(4105 chars clean, from 6112 raw). Writing the raw response gives you a file
that opens with a paragraph of planning notes instead of the ADR.

**The duplicate H1 is the house style, not a bug.** `write_adr()` adds a
`# ADR-NNNN: <title>` header *and* the LLM's own content already begins with
`# ADR-NNNN: <title>`. The three pre-existing ADRs (0009, 0014, 0016) all have
the same duplicate. Do not "fix" it — it makes the new ADR inconsistent with the

while all three providers returned 403 and **zero prose pieces were written**.
`run_once()` prints the failure and returns exit 0; the commit step then finds

The step's own `ls -la prose/snowball-inspired/ | tail -8` printed the **old**
files, so the log looked like it had produced something.

**The fix is an assertion, not a better exit code:** diff the artifact
directory before and after, or grep the log for the writer's success marker.
`.github/workflows/bruno-adr.yml` (added here) does this — it fails unless
`git status --porcelain bots/bruno-architect/adrs/` is non-empty, and it probes
the vault directly so the log names the real cause.

Corollary: **when a green CI run contradicts the artifact, read the run's raw
logs.** `GET /repos/{owner}/{repo}/actions/runs/{id}/logs` with `curl -L` returns
plain text (the API's `Content-Type` is misleading; it is not a zip), while
`GET .../actions/jobs/{job_id}/logs` needs `actions:read` and 403s without it.
The `??` step conclusions in the jobs API hide the real output.

## 6. Cheap mechanical gotchas

- `gh` is not installed. Use `curl` + `$GITHUB_TOKEN` against `api.github.com`.
  The token is org-scoped for `SuperInstance` and can write to `AI-Writings`.
- The REST **core** rate limit is often exhausted (5000/5000) in this sandbox, so
  `/user` and `/contents` 403 with "API rate limit exceeded". **`/search/*` and
  GraphQL have their own budgets** and still work — use search to find things
  when core is dry. A 403 body is the only way to tell a rate limit from a real
  permission error; never report a rate-limited 403 as "not found".
- `GET /repos/{owner}/{repo}/actions/workflows` lists workflows **from the default
  branch only**. A `workflow_dispatch` on a file that exists only on a feature
  branch 404s until the file lands on `main`.
- The repo is 3.7 GB. A full `git clone` is ~2.1 GB and slow; `git clone
  --filter=blob:none --no-checkout` is ~5 MB, then `git sparse-checkout set
  <dir>` fetches only what you touch. But a blobless clone still has to fetch
  the blobs for the paths you check out, so budget the time.
- `git sparse-checkout disable` on a 3.7 GB repo takes minutes and can wedge
  behind a stale `.git/index.lock` — `rm -f .git/index.lock` and re-run
  `git sparse-checkout set <narrow-path>` instead of disabling it.
- The repo **moved**: `SuperInstance/ai-writings` -> `SuperInstance/AI-Writings`.
  The API accepts the old name; `git push` prints the new location.
- `git` needs `user.name`/`user.email` set per-repo; there is no global identity.
- GitHub Actions runners spend ~80 s checking out this repo. Don't dispatch a
  workflow to learn something the API can answer in one call.
