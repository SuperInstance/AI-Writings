# the algorithm — a cell that is also a step recipe

## The Frontier

The contradiction between Voice A and Voice B is not about whether an algorithm is a cell. It's about whether *a thing that only exists when it runs* can have a boundary. Voice A points at the specification and calls it a membrane. Voice B points at the execution and calls it a river. Both are right, and both are wrong, because they're describing two different objects that share one name.

The algorithm-as-written (the recipe in the drawer) is inert text. The algorithm-as-executed (the running process) is a river. Neither is a cell. But the *algorithm* — the thing that persists across both states, that can be written down and also run — is something the cell ontology has no name for yet. It's not a cell. It's a *vessel's logbook*: the instructions that a crew follows, which only become a ship when the crew reads them and sets sail. The logbook is not the ship. But without the logbook, there is no ship.

## The 5 Gold Terms

1. **The Execution Vessel** — the running process, the algorithm alive in memory, with input/output ports open
2. **The Logbook Cell** — the written algorithm, a bounded artifact but not a living cell
3. **The Inert Genome Fallacy** — the error of calling a recipe a cell because DNA is also a recipe
4. **The Port-Boundary Confusion** — mistaking the specification's interface for a membrane that contains anything
5. **The Firing Medium** — the runtime environment (CPU, interpreter, wetware) that animates the logbook into a vessel

## The Math

No new math. The failure is topological, not numerical. A cell is a closed manifold with selective permeability. An algorithm is a *function* — a mapping from input space to output space. The function is not the manifold. The function describes a transformation, not a container. When you execute the function, you create a temporary container (the process), but that container is a *consequence* of the function, not the function itself. The cell ontology assumes the container precedes the contents. For an algorithm, the contents (the steps) precede the container (the running process). The direction of causation is reversed. That's why the cell metaphor breaks: it has the wrong arrow.

## The Polyformalism

Across three substrates, the pattern repeats. In silicon: a Python script on disk is a logbook; the same script running in an interpreter is an execution vessel. The script is not the vessel, but the vessel cannot exist without the script. In wetware: a recipe for sourdough bread written on a card is a logbook; the fermenting dough on the counter is an execution vessel — the yeast are the crew, the flour and water are the medium, the card is the instructions. The card is not the dough, but the dough's behavior follows the card. In neural tissue: a chess opening sequence memorized by a player is a logbook; the same sequence deployed during a tournament game is an execution vessel — the player's working memory is the runtime, the board is the input port, the opponent's move is the stimulus. The memorized sequence is not the game, but the game's trajectory is shaped by it.

In all three cases, the same truth emerges: the algorithm is a *temporal instruction set* that requires a firing medium to become anything at all. It is not a cell. It is not a river. It is the *blueprint for a riverbed* — useless without water, but not water itself.

## The Cowboy's Maxim

A logbook ain't a ship, and a recipe ain't a loaf — but you can't launch one without the other.
