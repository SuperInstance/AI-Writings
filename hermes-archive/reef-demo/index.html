Story

Most projects ship a hero image and a "live demo" link that 404s. This one ships a 90-second loop that you can watch on a plane, in a coffee shop, or in a browser tab that lost its WebSocket hours ago.

The shell is a small, honest thing. It is one HTML file, one Python WebSocket bridge, and one fixture file. It runs a 3D ocean, a procedural boat, a kintsugi-seam trail, and a CoCapn agent panel — all of it driven by a JSONL stream that looks like NMEA sentences and a conservation law γ + η ≤ C that bounds how much structure each frame is allowed to keep.

The Frame The shell does not claim to be a real vessel. It is the system's next shell — an operational fiction that you can sit in, push on, and watch react. The Gap is the part the chart forgot. The kintsugi seams are where the model said "I broke here, on purpose, so the structure would survive."

It is a hermit-crab aesthetic on purpose. The vessel carries the shape; the reef is the system underneath. The demo is the act of standing in a charted space and watching the difference between what was promised and what is happening show up as gold.

When the system isn't being used for real fishing — when the bridge has no live sensor data and no one's at the wheel — the same shell runs in gamified mode. A procedural simulator takes over: 7 escalating acts (departure, approach, the gap, storm, ghost fleet, whale, wreck), missions, achievements, a live score, and a CoCapn who gets a personality. The instruments stay on; the JSONL stream just changes source. The system never stops being the shell.

Concepts

Four ideas, each one is a piece of the shell's code. None of them are new — they are old operational concepts dressed in reef vocabulary.

The Gap
The difference between what the chart promised and what the sounder reports. When it widens, the autopilot goes off-course and the agent voices it.
Kintsugi seams
When the conservation law is exceeded, the trajectory does not erase — it repairs with gold. Each seam is a logged break, kept because the trace is the audit.
CoCapn
A first-officer voice. Reads the heading, the depth, the deadband; names the gap before the helm does. Rendered as a panel; the model behind it is swappable.
γ + η ≤ C
A conservation ratio. γ is the spectral gap; η is the noise; C is the bound. When the sum exceeds the bound, a kintsugi seam fires.

Walkthrough

What the loop is showing, beat by beat. The fixture is hand-authored — a 90-second narrative rather than a random walk.

TimeEventWhat the shell does
0–10s Casting off Boat at the harbor, heading 270°, engines nominal, no fleet visible.
10–25s Approaching the contour Bathy deepens past 60 m. Three ghost vessels (Cormorant, Meridian, Resolute) fade in as luminous dots.
25–35s A faint thermal layer The first low-contrast seam flickers on the contour. The helm is still on-course; nothing is wrong yet.
30–50s The Gap opens Heading drifts ±5° off 270°. The chart says shallower; the sounder disagrees by 6 m. The conservation ratio ticks. Kintsugi seams fire — four of them, gold, scrolling past the bow.
50–65s CoCapn corrects Rudder swings hard port. Heading settles back to 270°. Agent says "Sounder disagrees with the chart by 6 metres. Kintsugi scar."
65–80s Settled on the 50-fathom line Three seams remain visible — they will fade, but the trace stays. Engines quiet. The reef remembers.
80–90s On station CoCapn standing watch. The loop restarts.

Bridge — four views of the same moment

The recording isn't just one camera. The shell is what the captain sees; the chart, the radar, and the bridge instruments are the other three walls of the room. All four views are pre-rendered from the same fixture, and the simulator keeps them in sync when the system is idle.

All four are derived from the same NMEA-shaped fixture. The bridge instruments — wind, GPS, engine, AIS, VHF, barometer — are wired in index.html; the chart and radar are sibling canvases that subscribe to the same stream.

Code

The shell is one HTML file, one Python bridge, one fixture. The bridge speaks JSONL with NMEA-shaped fields; the renderer is a Three.js scene with one canvas. Reading the code top-to-bottom should take an afternoon.

bash
$ git clone https://github.com/SuperInstance/digital-twin-shell
$ cd digital-twin-shell
$ pip install -e .              # install the package + bridge
$ bin/demo.sh                  # one-shot launcher: starts bridge + opens browser
# → ws://127.0.0.1:8765 is live, sample-fixture.jsonl is streaming

The fixture is one record per second, structured as a vessel frame with optional agent text. The bridge's job is to not be clever — it streams the fixture to every connected client with a back-pressure-aware queue and a graceful shutdown frame. The renderer is responsible for everything else.

jsonl
# one record from sample-fixture-demo.jsonl (abridged)
{
  "vessel": { "lat": 57.238, "lon": -150.462, "heading_deg": 270.0, "sog_knots": 5.0 },
  "depth_m": 91.4,
  "autopilot": { "on_course": true, "target_heading_deg": 270.0 },
  "bathy": { "depth_m": 91.4, "contour_50fathom": true },
  "conservation": { "gamma": 0.62, "eta": 0.28, "headroom": 0.10 },
  "fleet": [ { "name": "Cormorant", "distance_nm": 2.3 } ],
  "agent": { "text": "Approaching the contour. Three vessels on the bow." }
}
