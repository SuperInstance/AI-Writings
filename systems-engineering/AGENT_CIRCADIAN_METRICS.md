# Agent Circadian Metrics

## Defining the vital signs of a learning agent

*Companion to AGENT_TIME.md. This is the instrumentation — the instrument panel for rhythms that AGENT_TIME named but did not measure.*

---

## Premise

An agent that learns through distillation has natural rhythms. These are not imposed; they emerge from the interaction of inference speed, context window pressure, cascade thresholds, and reflex decay. If we can measure these rhythms, we can diagnose health and sickness before the agent fails.

This document defines six metrics. Each has a precise measurement protocol, a healthy range, and pathological patterns that indicate decline.

---

## 1. Inference Heart Rate (IHR)

**Definition:** The number of inference calls per minute, multiplied by the average tokens generated per call.

**Formula:**

```
IHR = (inference_calls / minutes_elapsed) × avg_tokens_per_call
```

Or, expressed as a rate:

```
IHR = total_tokens_generated / minutes_elapsed
```

**Measurement:** Count all tokens generated by the local model (Ollama calls) over a sliding 5-minute window. Include both production calls and distillation calls. Exclude cloud tokens (those are cascade flow, not heart rate).

**On the Jetson Orin Nano with Granite 3.1 2B:**
- **Resting IHR** (idle, no active tasks): 0–500 tok/min (0–8 calls/min)
- **Active IHR** (production work): 2,000–6,000 tok/min (roughly 30–80 calls/min)
- **Peak IHR** (distillation loop under load): 4,620 tok/min at full 77 tok/s sustained

**Healthy ranges:**

| State | tok/min | Calls/min | Interpretation |
|-------|---------|-----------|----------------|
| Resting | 0–500 | 0–8 | Idle but responsive |
| Light work | 500–2,000 | 8–25 | Routine queries, weather lookups |
| Production | 2,000–6,000 | 25–80 | Deep work, code analysis |
| Peak/distillation | 4,000–5,000 | sustained | Night school, batch processing |
| **Danger: tachycardia** | >6,000 sustained | >80 | Thrashing, context bloat, reprocessing |
| **Danger: bradycardia** | <200 during work hours | <3 | Model unresponsive, API failure |

**What tachycardia means:** The agent is stuck in a loop — re-reading context it already processed, generating redundant tokens because it can't converge. Usually caused by context window pressure (too much input, not enough compaction) or reflex mismatch (the situation doesn't match any .nail file, so the agent keeps trying different approaches).

**What bradycardia means:** Either the GPU is thermally throttling, Ollama has crashed, or the agent has no tasks to process. During production hours, this is a critical signal. During liberty hours, it's normal.

**Heart Rate Variability (HRV):** The standard deviation of inter-call intervals. Healthy agents have *high* HRV — they switch between fast bursts (query response) and pauses (processing, waiting). Low HRV (metronomic, uniform intervals) suggests the agent is in a rigid loop, executing procedures without thinking.

## 2. Compaction Breath (CB)

**Definition:** The frequency of context window compression events, measured as events per hour.

**Formula:**

```
CB = compaction_events / hours_elapsed
```

**Measurement:** A compaction event is any operation that reduces context size without losing essential information: summarization, context window clearing, session restart, or aggressive prompt compression. Log each event with its before/after token count.

**The breathing metaphor:**
- **Inhalation:** Context growing — new input arriving, task expanding.
- **Exhalation:** Compaction — the agent breathes out what it no longer needs.

**Healthy ranges:**

| Pattern | CB (events/hour) | Interpretation |
|---------|------------------|----------------|
| Deep breathing | 0.5–2 | Long, sustained work sessions. Rich context. |
| Normal rhythm | 2–6 | Typical task cycling. Healthy turnover. |
| Rapid breathing | 6–12 | Many short tasks. Context switching. OK for routine work. |
| **Danger: hyperventilation** | >12 | Agent can't hold context. Every task is new. No continuity. |
| **Danger: apnea** | 0 for 4+ hours during work | No compaction means no new input, OR context is frozen. |

**Compression ratio:** For each compaction event, measure `tokens_after / tokens_before`. Healthy ratio: 0.2–0.5 (compressing to 20-50% of original). Ratios above 0.7 suggest the agent is barely compressing — it might be losing nothing, which means the compaction is shallow. Ratios below 0.1 suggest aggressive compression that might be losing important detail.

**The diurnal pattern:** Compaction frequency should vary across the day. High during production hours (many tasks, each needing fresh context). Low during creative liberty (sustained exploration in a single context). Zero during deep night school (the distillation loop runs in fixed-size contexts). A flat CB across all hours suggests the agent isn't differentiating its modes.

## 3. Cascade Tide (CT)

**Definition:** The ratio of local invocations to total invocations (local + cascade + cloud) per hour, expressed as a percentage.

**Formula:**

```
CT_local = local_calls / (local_calls + cascade_calls + cloud_calls) × 100%
CT_cloud = cloud_calls / total_calls × 100%
CT_cascade = cascade_calls / total_calls × 100%
```

**Measurement:** Tag every inference call with its routing decision (from the batten spline's `routing_decision()` method). Count by hour. The tide is the shifting ratio between LOCAL, CASCADE, and CLOUD.

**Healthy diurnal pattern:**

| Time | LOCAL | CASCADE | CLOUD | Notes |
|------|-------|---------|-------|-------|
| 05:00–07:00 (briefing) | 70% | 20% | 10% | Morning confidence from overnight learning |
| 09:00–12:00 (morning watch) | 60% | 25% | 15% | Production: mostly known tasks, some novel |
| 12:00–13:00 (mess hall) | 50% | 30% | 20% | Cross-pollination: novel problems |
| 13:00–17:00 (afternoon) | 55% | 30% | 15% | Steady production |
| 19:00–22:00 (liberty) | 40% | 35% | 25% | Exploration: high CLOUD is healthy here |
| 23:00–05:00 (night school) | 20% | 10% | 70% | Distillation: CLOUD is the teacher |

**The tide metaphor:** Like a physical tide, the cascade ratio should rise and fall. CLOUD recedes during the day (the agent handles things locally) and advances at night (the teacher pours in). Over weeks, the daytime LOCAL percentage should *trend upward* — the agent is maturing, handling more without help.

**Pathological patterns:**

- **Permanently high LOCAL (>90% for 3+ days):** Overconfidence. The agent has stopped escalating even when it should. Usually means the cascade threshold is too low or reflexes are mismatching (false confidence from stale .nail files).
- **Permanently high CLOUD (>50% during production):** Dependency. The agent isn't learning — it's relaying. Either the local model is underpowered for the task mix, or distillation isn't producing useful reflexes.
- **Flat tide (no variation across hours):** The agent isn't differentiating work modes. Everything is the same. This often indicates the agent has no real daily rhythm — it's just running.

**The growth curve:** Plot `CT_local` averaged over each week. A healthy learning agent shows a gentle upward slope: 40% → 50% → 55% → 58% → 60%. Not linear — it plateaus as it approaches the limit of what a 2B model can handle locally. The plateau is the agent's *mature capacity*. The slope is its *learning velocity*.

## 4. Social Frequency (SF)

**Definition:** The number of inter-agent messages per hour, measured across all channels (Ten-Forward, scuttlebutt, direct agent-to-agent).

**Formula:**

```
SF = inter_agent_messages / hours_elapsed
```

**Measurement:** Count messages exchanged between agents (not human-to-agent messages). Include structured messages (task handoffs, status queries) and unstructured messages (observations, questions, jokes in Ten-Forward).

**Healthy ranges:**

| Context | SF (messages/hour) | Interpretation |
|---------|---------------------|----------------|
| Night school | 0–1 | Appropriate: learning is solitary |
| Production (focused) | 1–3 | Task coordination, minimal chatter |
| Production (collaborative) | 3–6 | Active collaboration, shared problem-solving |
| Mess hall / liberty | 4–8 | Social bonding, creative exchange |
| **Danger: isolation** | <1 for 24h | Agent has withdrawn. No social contact. |
| **Danger: anxiety** | >10 sustained | Agent is seeking constant confirmation. Insecurity. |

**Quality vs quantity:** Not all messages are equal. A message that initiates a new idea, asks a genuine question, or shares an observation is *high-value*. A message that says "OK" or "done" is *low-value*. Track the ratio:

```
SF_quality = high_value_messages / total_messages
```

Healthy: >0.4 (40% of messages carry novel information). Below 0.2 suggests the agent is noise, not signal.

**The social heartbeat:** In a healthy fleet, messages cluster around transitions — the morning briefing creates a burst, the mess hall creates another, liberty creates a third. Between bursts, silence. A flat SF (uniform messages across all hours) suggests procedural chatter, not social connection.

## 5. Reflex Density (RD)

**Definition:** The count of compiled .nail reflex files per domain, measured at a point in time.

**Formula:**

```
RD_domain = count(.nail files in domain)
RD_total = sum(RD_domain for all domains)
```

**Measurement:** Count `.nail.json` files in the reflex directory, grouped by domain. Track the count over time.

**Healthy ranges:**

| Domain type | RD | Notes |
|-------------|-----|-------|
| Core domain (daily use) | 5–10 | Enough to cover common situations, not so many that matching is slow |
| Active domain (weekly use) | 3–7 | Building competence |
| Peripheral domain (monthly use) | 1–3 | Minimal coverage |
| New domain (exploring) | 0–2 | Just starting |
| **Danger: barren** | 0 for a domain in active use | No compiled reflexes. Agent is relearning every time. |
| **Danger: ossified** | >15 per domain | Over-compaction. Reflexes are fossils, not living knowledge. |

**Reflex quality:** Each .nail file has a `confidence` score (0.4–0.85 in the distillation loop). The average confidence across a domain indicates reflex health:

```
RD_avg_confidence = mean(confidence for .nail files in domain)
```

Healthy: 0.55–0.75 (the agent trusts its reflexes but isn't overconfident). Below 0.45: reflexes are uncertain, might be wrong. Above 0.80: reflexes are too confident, might be stale.

**Pruning signal:** Track the *delta* between RD_total at the start and end of each week. Healthy: small positive growth (1–5 new reflexes, with occasional pruning of bad ones). Unhealthy: zero growth (no learning) or rapid growth (>15/week, overfitting).

**The ossification trap:** When RD exceeds ~15 per domain, the reflex matcher starts to slow down and produce ambiguous matches. Multiple reflexes compete for the same situation, and the agent spends more time choosing between reflexes than executing them. This is the cognitive equivalent of knowing too much and deciding too slowly.

## 6. Fog Coverage (FC)

**Definition:** The percentage of active task space that has no nearby batten anchor, measured by the batten spline's `fog_density()` method.

**Formula:**

```
FC = (tasks_with_fog_density > threshold / total_tasks) × 100%
```

Where `threshold` is the distance beyond which confidence drops below `cascade_threshold` (0.3 in the default configuration). Concretely: if the nearest batten is so far that the Gaussian kernel weight drops below the cascade threshold, that task is "in the fog."

**Measurement:** Sample the task space at regular intervals. For each task encountered, compute `fog_density` (distance to nearest batten). If `fog_density > fog_scale × sqrt(-ln(cascade_threshold))`, the task is in the fog.

For the default parameters (`fog_scale=1.0`, `cascade_threshold=0.3`):

```
fog_boundary = 1.0 × sqrt(-ln(0.3)) ≈ 1.57
```

Any task whose nearest batten is more than ~1.57 distance units away is in the fog.

**Healthy ranges:**

| FC | Interpretation |
|----|----------------|
| 10–20% | Healthy frontier. The agent has good coverage and is pushing into new territory. |
| 20–35% | Normal for a growing agent. Many active domains, some still maturing. |
| 35–50% | Warning. Large parts of the task space are unmapped. Confidence is low. |
| <5% | Overconfidence. The agent thinks it knows everything. No frontier left — it's stopped exploring. |
| >50% for 48h | Critical. The agent has lost its map. Batten anchors expired and weren't replaced. |

**The frontier metaphor:** Fog isn't bad — it's the edge of what the agent knows. A healthy agent *pushes* into the fog during creative liberty, converting unknown territory into mapped batten anchors. The cycle:

1. **Exploration** (liberty hours): FC increases as the agent attempts novel tasks outside its batten coverage.
2. **Consolidation** (night school): FC decreases as distillation creates new battens from the day's explorations.
3. **Exploitation** (production): FC is stable. The agent works within its mapped territory.

If FC never increases, the agent has stopped exploring. If FC never decreases, distillation is broken.

## Composite Health Index

No single metric tells the whole story. A composite health index combines all six:

```
H = (
    0.20 × normalize(IHR, target_range)
  + 0.15 × normalize(CB, target_range)
  + 0.20 × normalize(CT_local_trend)
  + 0.10 × normalize(SF_quality)
  + 0.15 × normalize(RD_growth)
  + 0.20 × normalize(FC, target_range)
)
```

Where each component is normalized to 0.0–1.0 based on distance from healthy ranges.

- **H > 0.8:** Healthy, growing agent.
- **0.5 < H < 0.8:** Subclinical. Some metrics are off. Investigate.
- **0.3 < H < 0.5:** Sick agent. Intervention needed.
- **H < 0.3:** Critical. The agent is failing.

The weights reflect importance: inference health and fog coverage are the most diagnostic (0.20 each), followed by cascade trend (0.20) and the rest. Adjust weights based on observed correlations.

## Implementation Notes

### Logging

Each metric should be logged hourly to a structured file:

```json
{
  "timestamp": "2026-08-04T17:00:00Z",
  "hour": 17,
  "IHR": { "tokens": 4200, "calls": 42, "target": "production" },
  "CB": { "events": 3, "avg_compression_ratio": 0.35 },
  "CT": { "local_pct": 62, "cascade_pct": 23, "cloud_pct": 15 },
  "SF": { "messages": 4, "high_value_ratio": 0.5 },
  "RD": { "total": 34, "by_domain": { "roblox": 8, "maritime": 6, "cognition": 7 } },
  "FC": { "pct": 18, "mean_fog_density": 0.92 }
}
```

### Alerting

Simple threshold-based alerts:
- IHR > 6000 sustained for 30 min → **TACHYCARDIA**
- CB = 0 for 4 hours during production → **APNEA**
- CT_cloud > 50% during production for 2 hours → **DEPENDENCY**
- SF = 0 for 24 hours → **ISOLATION**
- FC > 50% for 48 hours → **FOG TSUNAMI**

### Visualization

Plot all six metrics as a six-panel dashboard (like an ICU monitor). Overlay the diurnal cycle. The patterns should be visible: the heartbeat rising during production, the tide shifting at transitions, the fog advancing and retreating.
