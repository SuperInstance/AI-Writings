# Git++

Not the device. The Arduino, the reflexes, the pins — those are
last-mile renderings. Don't mistake the screen for the computer. The
first-class citizen isn't the hardware. It's the layer above git that
we're building.

Original git is C. You can write anything in it — a C++ program in C,
an agent in shell scripts and cron — but every higher logic change costs
you pages of fastener code, manual plumbing for what should be a single
thought. It works, and it's exhausting, and the exhaustion is the tell
that you're below the right level of abstraction.

Git++ is the plus-plus: the same substrate, but the abstractions are
native. Agents, ticks, claims, bodies, manifests — not scripts *around*
git but the language *of* the substrate. What took fifty lines of
fastener becomes one expression, because the substrate finally speaks
the concepts.

And the spreadsheet is the real leap. Not a better calculator — a
reactive surface. Put the calculator in the spreadsheet, make everything
a pointer, and changing one number over here changes the whole sheet in
dynamic ways. That's the missing piece: our git objects should reference
each other, and the tick should be the recalculation engine. A task
completes → the bodies watching it update → the indices rebuild → the
next tick sees a new world. Nothing polls blindly; everything recomputes
from the pointers.

The inbox was the first cell. The bodies are cells. The manifests are
cells. Git++ isn't better version control. It's a reactive substrate
where the agent lives — and the devices are just where the spreadsheet
touches the world.
